# WORKING STANDARDS

1. Inspect existing code and documentation before making changes.
2. Preserve existing functionality and approved decisions.
3. Produce readable, maintainable and secure code.
4. Prefer established, actively maintained dependencies.
5. Never expose API keys, passwords, tokens or private credentials.
6. Use environment variables for application secrets.
7. Validate inputs and handle errors appropriately.
8. Add relevant automated tests for functional changes.
9. Run available tests and report actual results.
10. Never claim a test passed unless it was executed.
11. Document significant technical decisions.
12. Keep changes focused on the requested task.
13. Explain important security and compatibility risks.
14. Do not delete unrelated files or overwrite existing work.
15. Do not commit, push, deploy or publish without explicit approval.

# PROJECT ORGANISATION

Keep separate projects in clearly named directories.
Use descriptive filenames and meaningful Git commit messages.
Maintain appropriate README documentation.

# QUALITY CONTROL

Before finishing, review changes for correctness, security, maintainability and compatibility.
Clearly distinguish completed work from unverified assumptions.
